2PC의 한계: 긴 락과 조정자 SPOF

출처: 가상 면접 사례로 배우는 대규모 시스템 설계 기초 2, 12장 전자 지갑, p.411 · 그림 12.6

기다리는 동안 락이 잠겨 느리고, 조정자가 죽으면 진행이 멈춘다

1단계 요구사항 → 2단계 개략 설계 → 3단계 상세 설계 → 4단계 마무리          2-2. 2PC

그림 12.6 (adapted) 조정자 장애 (준비 단계 도중 ‘× 장애 발생’)

1. 저수준 방안
준비 단계를 위해 DB의 트랜잭션 실행 방식 변경 필요 — 이기종 DB면 모두 X/Open XA 표준을 만족해야 함

2. 성능
다른 노드의 메시지를 기다리는 동안 락이 오래 잠김

3. SPOF
조정자 장애 시 DB의 yes 응답이 전달되지 못함 → 조정자가 단일 장애 지점

출처: 가상 면접 사례로 배우는 대규모 시스템 설계 기초 2, 12장 전자 지갑, p.414 · 표 12.3

1단계 요구사항 → 2단계 개략 설계 → 3단계 상세 설계 → 4단계 마무리          2-3. TC/C

첫 번째 단계두 번째 단계: 성공두 번째 단계: 실패

출처: 가상 면접 사례로 배우는 대규모 시스템 설계 기초 2, 12장 전자 지갑, p.418–420 · 그림 12.13

n개 연산이면 보상 연산까지 2n개를 준비한다

그림 12.13 (adapted) 사가 작업 흐름

1. 모든 연산을 순서대로 정렬 — 각 연산은 자기 DB에 독립 트랜잭션으로 실행

2. 첫 번째부터 마지막까지 순서대로 실행 (한 연산이 끝나면 다음 연산)
